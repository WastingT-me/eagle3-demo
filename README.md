# EAGLE-3 DEMO

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/WastingT-me/eagle3-demo/blob/main/colab/eagle3_demo.ipynb)

Демо спекулятивной генерации EAGLE-3 команды [yandex-research-program-eagle3](https://github.com/stepankulibaba/yandex-research-program-eagle3): две модели из пула генерируют один ответ одновременно, страница показывает их скорость и дерево драфтера.

- `site/demo.html` — генерация двух моделей на выбор («Модель 1» и «Модель 2»); с движком `eagle` видно дерево драфтера на каждом шаге. Внизу страницы команда; `site/index.html` переадресует на `demo.html`.
  Фоном страницы играет видео из папки `videos` на Google Диске (первое по имени), а вместо его звука по кругу играет первый mp3 (или другой аудиофайл) из той же папки; без аудиофайла звучит само видео. Ноутбук подключает Диск, копирует папку на диск Colab и запускает сервер с `--videos /content/videos`; сервер отдаёт списки видео и музыки на `/api/videos`, а файлы на `/videos/...`. Без сервера (витрина на GitHub Pages) страница берёт файлы из `site/assets/...`, если они есть (их имена задаются в `site/assets/background.js`).

Пул из четырёх моделей, все держатся на GPU сразу (DeepSeek - если хватает памяти). В списках на странице перед подписью стоит `[target]` или `[draft]`:

| id | на странице | веса | что внутри |
|---|---|---|---|
| `llama` | [target] Llama-3.1-8B-Instruct | `meta-llama/Llama-3.1-8B-Instruct` (закрыта лицензией, нужен `HF_TOKEN`) | — |
| `authors` | [draft] authors | `yuhuili/EAGLE3-LLaMA3.1-Instruct-8B` | драфтер под Llama, слои 2, 16, 29 |
| `ours` | [draft] ours | `Funmagster/EAGLE3-Llama-3.1-8B-Instruct-L16-22-29-fcnorm` | драфтер под Llama, слои 16, 22, 29 и `fc_norm` |
| `dsl` | [target] DeepSeek-R1-Distill-Llama-8B | `deepseek-ai/DeepSeek-R1-Distill-Llama-8B` | модель с рассуждением; необязательная (`=optional`): грузится последней и только если хватает видеопамяти, иначе в списке с пометкой «не загружена» |

Оба драфтера обучены под Llama-3.1-8B-Instruct и ускоряют её. Другой таргет со своими драфтерами добавляется строками в `TARGETS` и `DRAFTERS` ноутбука (у драфтера четвёртое поле - id его таргета); честное сравнение скорости только внутри одного таргета.

Слои считаются как в коде авторов: i = вход слоя i (в SGLang и NeMo это выход слоя i−1, у нашего драфтера 15, 21, 28).

Если демо-сервер не запущен, страница демо проигрывает запись из `site/replay/sample.json`. Сейчас там **синтетический пример** из режима имитации; после первого показа замените его записью живого запуска (см. ниже).

## Структура

```
backend/engine_sglang.py  движок «sglang»: серверы SGLang, как в NeMo (serve/bench_sglang) и final_eval.py
backend/engine.py   движок по умолчанию «eagle»: пошаговая генерация на коде авторов, отдаёт дерево и принятый путь на каждом шаге
backend/eagle_patch.py  патч кода авторов под наши драфтеры (слои из конфига, fc_norm, строгая загрузка)
backend/server.py   FastAPI: /api/info (пул моделей), WebSocket /api/run ({"lanes": [m1, m2], ...}), раздача site/
backend/race.py     чередование шагов двух моделей по часам GPU
backend/mock.py     имитация без GPU (тот же протокол, ненастоящие цифры)
site/               статический сайт, работает и с GitHub Pages, и с самого сервера
backend/setup_engine.sh  установка зависимостей движка (её зовут ноутбук и сервер при смене движка)
colab/eagle3_demo.ipynb   запуск на Colab Pro+ с туннелем Cloudflare (код демо упакован внутрь)
tools/build_notebook.py   пересобирает ноутбук из backend/ и site/: python tools/build_notebook.py .
```

## Два движка

По умолчанию работает код авторов (`eagle`): на странице видно дерево драфтера. Поле «Движок» на странице меняет его на SGLang и обратно, с предупреждением, что это порядка 10 минут. Сервер (`POST /api/engine`) ждёт конца текущей генерации, ставит зависимости другого движка скриптом `backend/setup_engine.sh` (его же зовёт ноутбук; SGLang ~5 ГБ в окружение `/content/sgl`, повторно не ставится), гасит модели и серверы SGLang и перезапускает себя тем же процессом (`os.execv`) с `--engine` другого движка и теми же флагами. Сайт отвечает сразу, модели грузятся в фоне: `/api/info` отдаёт `state` loading → ready (или failed), страница показывает ход смены и сама подключается, когда модели готовы. Если установка не удалась, остаётся прежний движок, а страница показывает ошибку. Сменить движок может любой, у кого есть ссылка на демо.

| | `sglang` | `eagle` (по умолчанию) |
|---|---|---|
| что это | по серверу `sglang.launch_server` на модель, флаги как в `big-training/code/final_eval.py` | код авторов EAGLE (cb7e084) с патчем `eagle_patch.py` |
| скорость | как в замерах команды на SGLang | медленнее (eager PyTorch) |
| дерево драфтера | нет, только принятые токены за шаг | да, на каждом шаге |
| `fc_norm` | пакет `sglang_eagle31` из репозитория нашего драфтера | через патч |
| генерация | обе модели генерируют одновременно, два сервера делят GPU | шаги двух моделей чередуются |

Дерево в SGLang: `--speculative-num-steps 8 --speculative-eagle-topk 10 --speculative-num-draft-tokens 60`, это то же дерево статьи (8 шагов = глубина 7). Сервер: fp16, triton-внимание, без radix-кэша, `--random-seed 0`, по одному запросу за раз. Время шага в SGLang меряется по приходу кусков потока на том же компьютере, как HTTP-замер в `sglang_client.py`.

Драфтер для SGLang: сервер сам делает рядом копию каталога со ссылками на веса и правит `config.json`: архитектура `LlamaForCausalLMEagle3` (у авторов `LlamaForCausalLM`, на нём SGLang падает) и, если слои заданы через `eagle_capture_layers`, `eagle_config.eagle_aux_hidden_state_layer_ids` в счёте SGLang (на 1 меньше). Это то же, что `orchestrate.sglang_draft` в репозитории команды.

Версия SGLang: 0.5.9, как в замерах команды и в карточке нашего драфтера. Ноутбук ставит её в отдельное окружение на Python 3.12 (`uv venv`): SGLang тянет `outlines_core==0.1.26`, у которого нет готовых сборок под Python новее 3.12, и на Python Colab `pip install sglang` падает на сборке outlines_core из исходников на Rust. Сервер демо запускается питоном этого окружения.

Наш драфтер везёт в репозитории пакет `sglang_eagle31`. Движок находит его в скачанном каталоге драфтера и подключает ко всем серверам через `SGLANG_EXTERNAL_MODEL_PACKAGE`, как `launch_server.sh` нашего драфтера. Пакет добавляет `fc_norm` (без него SGLang 0.5.9 молча выбрасывает эти веса) и чинит баг 0.5.9, из-за которого CUDA-графы снимали слои таргета по умолчанию 2, 16, 29 вместо слоёв драфтера (−13 % τ). На официальный драфтер и таргеты он не влияет. Драфтер с `norm_output` (второй переключатель EAGLE-3.1) на SGLang 0.5.9 не загрузится с понятной ошибкой: его нет ни в 0.5.9, ни в пакете.

Память: каждый сервер SGLang держит свою копию таргета, 8B в fp16 - это ~16 ГБ, движок закладывает 20 ГБ на модель. Все три модели сразу помещаются на 80 ГБ (H100, A100 80 ГБ); если памяти мало, сервер не стартует и пишет, что делать. На 40 ГБ берите движок `eagle`: там одна копия таргета на все драфтеры, и всё помещается. `--max-servers N` включает старый режим, когда модели меняются на GPU по очереди. При выгрузке модели движок ждёт, пока сервер отдаст память, а при старте добивает серверы SGLang от прошлого запуска.

## Показ через Colab Pro+

1. Откройте ноутбук значком «Open in Colab» вверху (или File → Upload notebook с `colab/eagle3_demo.ipynb`).
2. Runtime → Change runtime type → **H100** или A100 (40 или 80 ГБ); включите Background execution. Движок при запуске `ENGINE = "eagle"` (код авторов, с деревом); на странице его можно сменить на SGLang и обратно.
3. Добавьте секрет `HF_TOKEN` (значок ключа слева), предварительно приняв лицензию Llama-3.1-8B-Instruct на Hugging Face. Без токена демо не запустится.
4. Состав пула задают списки `TARGETS` и `DRAFTERS` в первой ячейке: таргет `(id, подпись, репозиторий)`, драфтер `(id, подпись, репозиторий, id таргета)`.
5. Runtime → Run all. Первый запуск ставит зависимости и качает ~18 ГБ весов, это 10–15 минут. Ячейка сервера печатает, какие модели загрузились; модель с битой ссылкой просто не попадёт в пул.
6. Последняя ячейка печатает ссылку вида `https://xxxx.trycloudflare.com/demo.html`. 

Адрес меняется при каждом перезапуске Colab.

## Свой драфтер на Hugging Face

В репозитории нужны `config.json` и `model.safetensors` (или `pytorch_model.bin`). Подходят обе раскладки весов: авторов (`midlayer.*`, `fc.*`, `fc_norm.*`, `norm.*`, `lm_head.*`, `d2t`, `t2d`) и NeMo / vLLM (`model.layers.0.*`, `model.fc_norm.*`).

Что сервер читает из `config.json`:
- `fc_norm: true` — RMSNorm на каждое из трёх состояний таргета перед `fc`;
- `norm_output: true` — финальная RMSNorm драфтера применяется к его выходу (только движок `eagle` или SGLang ≥ 0.5.12);
- слои таргета: `eagle_capture_layers` (счёт авторов) или `eagle_config.eagle_aux_hidden_state_layer_ids` (счёт SGLang/NeMo, на 1 меньше). Без них берутся 2, N/2, N−3.

Код авторов эти поля не знает, поэтому для движка `eagle` ноутбук патчит его (`backend/eagle_patch.py`). Перед каждым шагом каждой дорожки сервер выставляет слои её драфтера и её таргет, так что в одной генерации могут ехать драфтеры с разными слоями и разными таргетами. Если в конфиге `fc_norm`, а в весах его нет, драфтер не загрузится и ячейка сервера покажет ошибку.

## Как считаются цифры

- Время шага меряется только по работе GPU (с `torch.cuda.synchronize`), без декодирования текста и отправки по сети.
- Токены в секунду = сгенерированные токены / сумма времени шагов, включая prefill.
- Токены за шаг (τ) = сгенерированные токены / число проходов таргет-модели.
- Генерация в движке `eagle`: шаги двух моделей выполняются строго по очереди (GPU никогда не делится), вперёд всегда идёт модель с меньшим накопленным временем GPU. Браузер показывает обе дорожки по этим часам, поэтому сравнение честное, хотя на стене она идёт примерно вдвое медленнее, пока обе дорожки живы. У каждой модели свой KV-кэш, веса таргета общие для всех его драфтеров.
- Итог генерации: отношение токенов в секунду более быстрой модели к более медленной.
- Перед первым показом сервер делает прогрев.
- Температура: 0 даёт одинаковые ответы на обеих дорожках (спекулятивный декодинг не меняет ответ таргета). При 0.6 и 1.0 ответы различаются (семплирование), а τ обычно ниже.
- Дерево: 60 узлов, глубина 7, top-k 10, как в статье для EAGLE-3.
